This Data Processing Addendum ("DPA") forms part of the [Terms of Service](terms.md) (the
"Agreement") between `{{COMPANY}}` (the "Processor", "Operator") and the customer organization
that uses the Guide Engine service (the "Controller", "Customer"). It applies to the personal
data of the Customer's end users that the Processor processes on the Customer's behalf, as
described in section 3 of the [Privacy Policy](privacy.md). It does not cover the Processor's own
processing of Studio author accounts, for which the Processor is a controller.

## 1. Roles

- The **Customer is the controller** (or, where it acts for its own clients, a processor
  instructing the Operator as a sub-processor) of the end-user data that its websites send to
  the Service.
- `{{COMPANY}}` is the **processor**: it processes that data only to provide the Service and on
  the Customer's documented instructions.

## 2. Subject matter, nature and purpose

| | |
|---|---|
| **Subject matter** | Showing in-app guides on the Customer's websites and reporting how end users interacted with them. |
| **Nature of processing** | Receiving identifiers and usage events from the agent script in end users' browsers; storing them in the Service's database; serving the right guides to each visitor; aggregating events into analytics shown to the Customer's authors in the Studio; sampling and storing agent error reports; rate limiting by IP address; automated deletion by retention. |
| **Purpose** | The Customer's product guidance, onboarding and help-center functionality, and measurement of its effectiveness. |
| **Duration** | The term of the Agreement, plus the deletion period in section 9. |

## 3. Categories of data subjects and personal data

**Data subjects:** end users (visitors) of the Customer's websites on which the snippet is
installed, whether identified by the Customer (signed-in users) or anonymous.

**Personal data:**

| Category | Detail |
|---|---|
| Identifiers | The **visitor id** and optional **account id** the Customer's website passes in (the Customer chooses what these are), or a random anonymous id generated by the agent and kept in the browser's `localStorage` on the Customer's domain. |
| Usage events | Guide shown / step viewed / step completed / completed / dismissed / error, with guide, version and step, time, a per-page-load session id, and whether the guide was started from the help center; help-center opened and **searched** events including the search query (up to 200 characters) and result count. |
| Per-visitor state | Whether a visitor dismissed or completed each guide and which version they last saw. |
| Technical | Agent error reports: error message, stack trace, the **page URL** (up to 2000 characters), agent version, time. **IP address** held transiently for rate limiting (about one hour). |

**Special categories:** none intended. The Customer undertakes not to pass special-category
data, payment card data, health data, government identifiers or similar in identifiers, search
queries or page URLs, and to configure the Service accordingly.

## 4. Instructions

1. The Customer's instructions are: the Agreement, this DPA, the settings the Customer chooses
   in the Studio (applications, websites, signed identity, audience, help center, and switching
   applications and guides on or off), and the identifiers its websites pass to the agent.
2. The Processor processes personal data only on those instructions, unless required to by law,
   in which case it informs the Customer before processing where the law allows.
3. The Processor informs the Customer if, in its opinion, an instruction infringes applicable
   data protection law.

## 5. Confidentiality and personnel

The Processor ensures that persons authorized to process the data are bound by confidentiality.
By design, the Processor's staff cannot read the Customer's guide content, pages or per-visitor
state unless an **owner** of the Customer's organization grants **support access** in the Studio
(1 to 90 days, read-only, every request logged and visible to the Customer, revocable at any
time). Platform administrators otherwise see only organization names, owners, member,
application and guide counts and event volumes, for service administration.

## 6. Security measures

The Processor implements the technical and organizational measures summarized in section 7 of
the [Privacy Policy](privacy.md), including:

- per-organization and per-application isolation enforced in application code **and** by
  Postgres Row-Level Security on every table, with a database role that cannot bypass it;
- HTTPS for all traffic; OpenID Connect sign-in for the Studio with algorithm-pinned token
  verification;
- encryption at rest of application signing secrets (AES-256-GCM); hashed invitation tokens;
- per-website CORS, rate limiting, payload caps and no browser credentials on the public agent
  API; server-side sanitization of guide content;
- read-only, consent-based and logged staff access; logs without bodies, headers or tokens;
- `[the Processor's organizational measures: staff access control, backup encryption and
  testing, incident response, vulnerability and patch management, business continuity]`.

The Processor may update these measures provided the overall level of protection does not
decrease.
